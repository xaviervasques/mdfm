# MD_FM: the Movement Foundation Model

MD_FM is a measured-body foundation model of abnormal human movement. The model is one
anonymous 3D body, inferred as a posterior trajectory from whatever was recorded (video
keypoints, inertial sensors, force, EMG), with every MoveAtlas contract read as a physical
measurement of that body through a differentiable sensor kernel. A healthy prior over the
body's motion is learned on healthy movement and on virtual sensors rendered from it;
pathology is read from the body posterior against that norm as unit-bearing descriptors.
The design is in `docs/MFM_DESIGN_2026-09-24.md`.

Status: research code in development. No model weights and no result are published from
this repository yet. Each claim of the program is decided by a gate scored on a
subject-disjoint held-out split, under a rule written before the read; a rule file joins
this tree once it is registered by its SHA-256.

## Layout

```
mdfm/        the package: body model and kinematics, sensor kernels, data stores and
             samplers, the model (tokenizer, encoder, posterior, decoder, prior), training,
             readouts, gate harnesses, the neural descriptors, the synthetic patient
configs/     run configurations (3 files)
scripts/     185 measurement, build, training and evaluation scripts
tests/       110 test modules and their helpers
docs/        the design and its addendum, the architecture note, the model code spec
env/         the environment recipe (env/README.md) and its package lists
```

## Reproduction without registration

Everything in this repository reproduces without registration, without an email and
without asking for permission: every input it reads is openly licensed and anyone can
download it.

- the code: BSD-3-Clause (`LICENSE`);
- the Python packages: from PyPI and from the PyTorch package index (`env/requirements.txt`,
  the exact versions in `env/requirements-lock.txt`);
- the body model: Anny (`pip install anny==0.6.2`, in the recipe), code under Apache-2.0
  and model data under CC0 1.0; `mdfm/synth/openbody.py` refuses the Anny options that
  would need its separate non-commercial download;
- the data: the MoveAtlas sources that the open configurations (`configs/stage1_open*.yaml`),
  the open body store and the registered studies read, each under CC BY 4.0, CC0 1.0 or the
  CMU motion capture terms (free for all uses, no resale of the data), downloaded by the
  MoveAtlas fetch scripts from Zenodo, figshare or the CMU site, or from an open MoveAtlas
  copy on Zenodo where the original host asks for an account;
- the movement gallery of the synthetic patient: generated by `mdfm/synth` on Anny
  (`scripts/render_skeleton_catalogue.py`), its motion data under CC BY 4.0.

The first model of the program (v1) was trained on a body model and a motion corpus that
their owners distribute only after registration (SMPL+H and AMASS). Their code, their
configurations and the scripts that cannot start without them are not in this tree; a
script that reaches a v1 code path stops with an import error that names the missing
module. The open model is the v1 recipe on the open body and its open data.

## Install and test

The environment recipe is `env/README.md` (Python 3.11, PyTorch with CUDA, the packages
of `env/requirements.txt`). Then:

```bash
python scripts/check_env.py
python -m pytest -q -p no:cacheprovider tests
```

## Data

MD_FM reads the MoveAtlas corpus (https://github.com/xaviervasques/moveatlas) from a local
tree named by the variable `MOVEATLAS_ROOT`; the stores and run folders it builds live
outside the repository (`MDFM_BODY_STORE`, `MDFM_WINDOW_STORE`, `MDFM_GATES_STORE`,
`MDFM_RUNS`, `MDFM_SYNTH_VIEWER` for the synthetic patient's clips and gallery, `MDFM_ANNY_CACHE`
for the body model's cache). No data ship here: no MoveAtlas record, no body model file, no per-person
table.

Small run-time inputs without any person ship under `reports/` (19 files: sensor
noise floors, the sensor layouts, the task table, the stage-2 summaries and store hashes, the
counts per source and tier, the SHA-256 of the held-out file as a public commitment, the
open model's priors, mounting priors, layouts and joint-limit tables, the open body's rest
basis, and the synthetic patient's catalogue body and folded-arms posture, each built by a
shipped script). The package also reads run-time inputs from `reports/`
and `docs/rules/` of the working tree that are not in this tree (16 paths: the v1
priors, folds, the gate rule drafts and the held-out membership, among others). The held-out
membership and the person maps stay private until the gate reads they protect are done; the
code that draws them ships (`scripts/build_tiers_and_lockbox.py`,
`scripts/build_person_map.py`). Machine-specific defaults are written as placeholders
(`<moveatlas>`, `<store>`, `<repo>`, `<home>`): set the variables above instead.

The program's standing rules: patient-level splits everywhere, the per-sample frame rate
everywhere, CODY used for evaluation only, raw identifiable data never leaves the local
disk, and the licence of every source checked before any derived release.
